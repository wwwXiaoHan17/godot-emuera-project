# 对比实验：文字控制台该怎么“换页”

三个最小样，内容差不多，只有“换页”的做法不同。你自己跑一遍看区别。
这些是临时实验文件，不是最终引擎，看完可以删。

| | A：常驻壳 | B：change_scene | C：混合（推荐） |
|---|---|---|---|
| 换页时换掉什么 | 什么也不换，只换代码 | 整棵场景树 | 壳里的一块内容 |
| 历史文字 | 一直在 | 换页就没 | 一直在 |
| 跨页流程（等待/下一句） | 不断 | 当场断 | 不断 |
| 特殊页面能在编辑器里摆 | 不能 | 能 | 能（插进壳里） |
| 每页重复背景/滚动区 | 不用 | 要 | 不用 |

## 怎么跑

用 Godot 4.8-dev7 打开本项目，分别双击下面三个场景、按 **F6**：

- `experiment/a_persistent_shell/a_main.tscn`（A 版）
- `experiment/b_scene_switch/b_page1.tscn`（B 版）
- `experiment/c_hybrid/c_main.tscn`（C 版）
- 另外：`experiment/c_hybrid/c_page_form.tscn`（C 版的特殊页面，可以单独 F6 跑）

## A 版：常驻壳 + 文本流

- 点“开始游戏”：文字**追加**在下面；往上滚，第一页的字还在。
- 选过的旧按钮会变灰、不能再点。
- “再印三十行”会自动滚到底；“返回标题”清屏回顶部。
- 全程不换场景。

## B 版：每页一个 .tscn，用 change_scene 当 goto

- 点“开始游戏”：整屏被换掉，页 1 的 10 行历史文字消失。
- 输出面板会看到故意的报错：`Invalid access to property or key 'process_frame' on a base object of type 'null instance'`
  —— 切场景的瞬间旧场景已经离树，里面的流程继续跑就断。
- “返回页 1”是重新创建页面，之前动态加的字不会回来。

## C 版：常驻壳 + 挂载式页面（混合）

- 点“开始游戏”：文字继续追加；接着出现角色创建页（一块 `.tscn` **插进壳的槽里**，不是换场景）。
- 表单里改名字、调年龄、勾特质，点“开始游戏”：页面被拿掉，数据交回流程，历史文字和滚动位置都还在。
- 对比 B：同样的“页面用编辑器摆”的能力，但控制台没有被连根拔掉。
- 关键代码只有一段：`add_child(page)` → `await page.finished` → `remove_child(page)`。

## 我跑出来的问题（修 A 版时踩到的）

1. 清屏时对“正在发 pressed 信号的按钮”调用 `free()`：报 `Attempted to free a locked object`，且清屏只做一半。→ 先 `remove_child`，再 `queue_free`。
2. 旧按钮不禁用：下一页的等待会把旧按钮的编号当成新选择。→ 选完把旧按钮 `disabled` 掉。
3. 加完文字马上滚到底：只等一帧还没排版，滚不动。→ 等两帧，按内容高度算目标位置。
4. 清屏后滚动位置与滚动条残留：画面空白、滚动条不消失。→ 滚动归零 + 强制重算最小尺寸。
5. （真实引擎还需要）文字行数上限，否则节点只增不减。

## 结论

- B 的问题是“换掉整棵树”，补代码救不回来：历史没了、流程断了、页面状态被重建。
- 最终形态 = **常驻壳（A）+ 场景只当挂载块（C）**；`change_scene` 只适合低频、整页、可清屏的边界（比如标题↔游戏），不用于事件跳转。
